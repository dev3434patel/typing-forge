# SparowType — Keyboard Awakens product audit

Audit date: **16 October 2026, Asia/Calcutta**. This report reviews the current working-tree implementation, not a deployed production service. It covers the typing engine, every routed page, shared interface, adaptive practice, results, account/storage boundaries, competition, offline support, metadata and release checks.

The product now has a coherent test → explanation → targeted practice → matched retest flow, with local-first records and a separate trusted server path. The new Keyboard Awakens opening, lime/purple dark theme, additional feedback controls, secondary pages, offline shell and period rankings are implemented in source. **The final coordinated verification below records the completed local checks and remaining release gates.** Hosted services, actual devices and field performance remain separate gates. No finite test suite establishes a universal zero-defect or “10000000% accuracy” guarantee.

The brand is **SparowType**. Existing `forge-v3` metric versions, comparison policies, owner-scoped `typingforge` storage identifiers and compatible history/export formats are intentionally retained. Visual changes and new pages do not rewrite earlier observed scores.

## 2. Accuracy: what the current result actually means

The metric contract is defined in [METRICS.md](METRICS.md) and `src/lib/typing-core`. Input accuracy counts committed insertion graphemes, including rejected and later corrected attempts. It is not a count of physical keydown events. Backspace, modifiers and navigation have separate roles and do not inflate the insertion denominator.

| Measure               | Current formula / policy                                                                                | Audit result                                                                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Input accuracy        | Correct insertion attempts ÷ all insertion attempts × 100                                               | A corrected error retains its original cost. Empty evidence is unavailable, not an invented 100%.                                                                       |
| Final text accuracy   | Final correct ÷ (correct + incorrect + extra + applicable missed) × 100                                 | Can be 100% after correcting text while input accuracy stays lower.                                                                                                     |
| Headline WPM          | Canonical credited units ÷ 5 ÷ active elapsed minutes                                                   | Prose credits complete correct words and applicable separators; the final timed partial word has a declared prefix policy. Code uses exact matching retained positions. |
| Correct-character WPM | Correct retained units ÷ 5 ÷ active elapsed minutes                                                     | A separately labelled result statistic exposes the character-based measure. It does not retroactively change headline WPM, PBs or historical records.                   |
| Raw WPM               | Retained units ÷ 5 ÷ active elapsed minutes                                                             | Retained text, including errors; deleted characters are no longer retained.                                                                                             |
| Attempt rate          | All insertion attempts ÷ 5 ÷ active elapsed minutes                                                     | Includes corrections/retyping attempts; separate from raw WPM.                                                                                                          |
| Consistency           | Duration-weighted variation of insertion-attempt buckets, including idle time                           | Requires five seconds and five attempts. This is rhythm consistency under the existing policy.                                                                          |
| Five-second burst     | Highest complete five-second insertion-attempt window on the declared grid/final window                 | Unavailable for shorter sessions; not inferred from the fastest isolated key.                                                                                           |
| Elapsed time          | First attempt to actual finish/deadline, including idle; explicit personal pauses excluded and recorded | Races/challenges use a server-owned start/deadline. An unused personal test does not start merely by focusing.                                                          |

**Two specification differences remain explicit.** The requested character-based primary WPM has not replaced the existing word-credit headline contract. The new correct-character statistic makes the difference visible. The requested consistency based on per-second correct WPM has not replaced the existing attempt-bucket rhythm formula. A future policy change needs a new metric/comparison version and a migration strategy; relabelling old values would make historical comparisons misleading.

For the supplied 30-second display, the following arithmetic is possible if 136 means correct retained characters, with 10 incorrect, one extra and one missed:

| Display                          | Calculation                     | Meaning                                                                  |
| -------------------------------- | ------------------------------- | ------------------------------------------------------------------------ |
| 86.5% input accuracy             | 135 ÷ 156 × 100 = 86.538…%      | 21 incorrect insertion attempts remain, even after editing.              |
| Approximately 92% final accuracy | 136 ÷ 148 × 100 = 91.891…%      | A final-text measure with a different denominator.                       |
| 59 raw WPM                       | (136 + 10 + 1) ÷ 5 ÷ 0.5 = 58.8 | 147 retained units.                                                      |
| 62 attempt rate                  | 156 ÷ 5 ÷ 0.5 = 62.4            | All insertion attempts.                                                  |
| 54.4 correct-character WPM       | 136 ÷ 5 ÷ 0.5                   | Character credit differs from word credit.                               |
| 44 word-credit WPM               | 110 credited units ÷ 5 ÷ 0.5    | Requires the actual canonical word-credit total to confirm this session. |

These calculations establish arithmetic consistency, not reconstruction of that user's session. Its exact word credits, 58% consistency and 84 burst require the original exported target, normalized edits, timing and pauses. The earlier synthetic witness proves that such totals can coexist; it is not the user's event log.

The earlier finite engine conformance checkpoint covered 13,640 independently referenced short prose vectors, 15,000 randomized ASCII range edits and 5,000 randomized Unicode range edits. The reference implementations do not merely repeat the canonical word-credit loop. Scope is still finite: native Unicode segmentation, IME delivery, OS/browser scheduling and adversarial histories extend beyond these vectors. See the retained [conformance evidence](METRIC_CONFORMANCE_2026-10-15.md).

## 3. Primary-source competitor comparison

Official sources were reviewed on **16 October 2026**. This is a feature/positioning comparison, not an independently measured global popularity ranking, revenue estimate or market-share study. Google Trends search-volume data could not be established during the research; no trend chart or fabricated volume is supplied.

| Product           | Officially evidenced strengths                                                                                                | Adopt / current SparowType comparison                                                                                                                                                                                                                                          | Remaining gap / opportunity                                                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Keybr**         | Per-key speed/error observations, weaker-key lessons and progressively introduced letters                                     | Adaptive engine distinguishes introduced, sampled, assessed and mastered states; per-key evidence can feed targeted practice. [Official repository](https://github.com/aradzie/keybr.com)                                                                                      | Predictive progression and educational effectiveness at real user scale are unverified. Different algorithms do not imply identical confidence values.        |
| **Monkeytype**    | Quiet inline input feedback, test modes/languages, punctuation/numbers, quotes, themes, smooth caret, history and challenges  | Text-first workspace, six modes, real wrong-key display, pace/caret preferences and a detailed result evidence path adopt these interaction principles. [Official README](https://github.com/monkeytypegame/monkeytype/blob/master/README.md)                                  | Its content/modifier/settings breadth is larger. Site-to-site speed equality requires matched formulas/content/settings; sharing a WPM label is insufficient. |
| **TypingClub**    | Structured instruction, hand-position guidance, progress levels and varied learning activities                                | Touch-typing guide provides a concrete beginner loop; adaptive lessons provide measured practice. [Official product page](https://www.typingclub.com/)                                                                                                                         | A full staged school curriculum, instruction videos, classes and comparable lesson breadth are absent.                                                        |
| **10FastFingers** | Normal/advanced timed tests, many languages and competitive modes                                                             | Timed practice, curated language packs, labelled local bots and a two-person server race implementation address part of this need. [Official test page](https://10fastfingers.com/typing-test)                                                                                 | Hosted multiplayer scale, larger public competitions and language breadth are not established here.                                                           |
| **Typing.com**    | Problem-key practice, daily goals, period-filtered statistics and class scoreboards; teacher reports support filtering/export | Individual daily goals, history filters, per-key evidence and exports exist. Real day/week public aggregates have now been added locally. [Student lessons](https://support.typing.com/en/articles/9047425), [Teacher reports](https://support.typing.com/en/articles/9048385) | Teacher/classroom management, standards reporting and classroom administration are not implemented.                                                           |

The strongest product direction is **explain the score → inspect actual mistakes → practice observed weak transitions/keys → retest the same passage with explicit repeated-content labels**. This is a design opportunity inferred from the comparison, not proof that no other product offers it. The Keyboard Lab adds browser-observed key/code/release signals with measured transition drills. It does not identify a keyboard model, switch, true device latency, finger placement or hardware failure. The browser layout-map API has limited availability and requires capability-aware handling. [MDN getLayoutMap](https://developer.mozilla.org/en-US/docs/Web/API/Keyboard/getLayoutMap)

Hardware recommendations were not converted into product truth. A tactile switch or expensive keyboard does not establish a universal accuracy guarantee. Training recommendations such as correction policy, broader vocabulary and punctuation are user-configurable practice choices, not proof of a particular outcome.

### Known limitations and requested-spec differences

1. **Performance retains the measured scope above.** The latest final-build mobile performance score is 53, below the requested 95 target. This release gate FAILED; a passing bundle gate or exact-input burst does not override it. A 4.2-second text-bearing opening competes with a 150 ms added-LCP target. The code drops desktop bloom on measured low FPS; native hardware, field INP and sustained thermals still need measurement. No hidden/reduced-motion-only score is presented as a full-intro score.
2. **Metrics remain compatible `forge-v3`.** Main WPM is word credit, not the requested character formula; a separate correct-character statistic is provided. Consistency uses weighted attempt buckets, not per-second correct WPM. Input accuracy counts committed insertion graphemes, not modifier/backspace keydown events. A new canonical policy requires versioned server/history comparisons.
3. **Focus behavior:** ordinary input blur preserves the session and idle time continues; personal practice has explicit Pause/Resume. Automatic pause-on-window/visibility-loss was not substituted. Races keep authoritative deadlines. This differs from the requested blanket automatic pause/resume.
4. Five sound choices are procedural synthesis, not five recorded commercial switch sample libraries. The probed Windows Playwright WebKit has no AudioContext API; its sound-only check is explicitly UNVERIFIED, while visual preferences and unsupported-device guidance remain tested. Native Safari gesture/audio behavior is independently UNVERIFIED. The CPU/mobile renderer deliberately uses simpler PBR and smaller textures; fallback uses HTML/CSS geometry rather than the WebGL dissolve shader.
5. A beginner guide and adaptive model do not constitute a complete TypingClub curriculum/classroom system. Content breadth, native script fonts/layouts, actual learning outcomes and engagement require further editorial and user validation.
6. Google Trends rising queries remain UNVERIFIED for all six terms across Worldwide/India/US. No result was inferred from roundups or normalized interest terminology.
7. Hosted Supabase Auth/Google OAuth/Edge/Realtime/cron, simultaneous clients, native Safari/iOS/Android, actual screen readers and install/eviction/update behavior remain UNVERIFIED. Public operator/legal details and the deployment origin still require the real environment.
8. Exact palette pair checks and a lab CLS observation do not establish full contrast/layout-shift conformance. Several non-Latin font fallbacks depend on installed system fonts; their size adjustment is not fully calibrated.

No finite test suite proves universal zero defects, physical keyboard identity, human typing or worldwide visual originality. The implementation is reviewable locally; the failed/unverified release gates above remain open.
