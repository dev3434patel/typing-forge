Focused units and scoped type/lint checks passed for their respective repairs. The implemented browser suites are part of the coordinated production matrix. A targeted checkpoint is not a blanket pass for the final build: the final upgrade audit owns the combined result, capability skips and outstanding deployment/native-device limits.

Regression coverage and boundaries:

1. Input integrity: native replacement/composition, current-word recovery, wrong-key feedback, focus/selection restoration and caret geometry.
2. Mobile presentation: 320/390 px, phone landscape, reduced motion, keyboard visibility, large text, update banners and scrolling reachability. Synthetic viewport resizing is not an actual soft-keyboard acceptance test.
3. Route lifecycle: countdown start/cancellation, local bot restart, result navigation, game entry/exit and observer cleanup. Game-specific state belongs to the new games suite.
4. Static deployment: Vercel root and GitHub Pages subpath routes, downloaded public practice and local persistence. Public ranked/human services remain unavailable in a frontend-only bundle.

Operating-system autocorrect, dictation, native dead keys/IME, VoiceOver/NVDA and physical Android/iOS visual viewports still need manual device testing. Measured local responsiveness must not be presented as a universal latency guarantee.

## Retained-text mobile input follow-up — 27 October 2026

The current [ordinary practice adapter](../src/components/typing/TypingArea.tsx), shared by tests, structured lessons and local bot practice, now listens to native `input` through one React `onInput` handler. Input-only `insertReplacementText` keeps its observed `autocorrect` provenance even when the browser supplies no preceding keydown or beforeinput. Ordinary `insertText` remains keyboard input; a replacement marker cannot leak into subsequent independent edits.

An unchanged replacement now records a zero-text `replace` event at the retained text's end. That event preserves assistance and comparison exclusion without adding insertion attempts, deletions or characters. An empty replacement before the first accepted insertion keeps practice ready and does not start its clock. Unchanged ordinary keyboard input remains a no-op; a canceled composition does not acquire a fabricated assistance marker.

The adapter also uses the existing [composition ownership guard](../src/lib/composition-echo.ts). It remembers the actual composition event's `data`, consumes only the next explicitly composition-owned matching batch, and clears ownership when an unrelated input or new composition arrives. A recognized final echo restores both the native textarea and controlled React value to the canonical transcript, including an echo that appends a decomposed committed batch again. A composition with no trailing echo can be followed by an independent native insertion and deletion without losing the deletion or desynchronizing the displayed text from its recorded transcript.

The [mobile input regression file](../e2e/mobile-input-integrity.spec.ts) contains eight test definitions: two existing adaptive provenance cases and six retained-text cases covering replacement versus ordinary input, unchanged replacements and their keyboard controls, composition without a trailing echo, and an explicit appended composition echo. **Browser result: PASS-SCOPED, 32/32 mobile-input cases** across Chromium, installed Edge, Firefox and bundled WebKit on source19 build `de097acba6969d580cc8`. The separately identified 16 PWA snapshot cases in the same [raw focus report](../audit/2026-10-21/final19-mobile-pwa-focus.json) bring that declared run to **48/48 passed**, with zero failures/skips/flaky cases/retries. The [summary](../audit/2026-10-21/final19-mobile-pwa-focus-summary.json) agrees with the raw report; the [protocol](../audit/2026-10-21/final19-mobile-pwa-focus-protocol.json) preserves unchanged build/tests/dependencies during that run. These browser fixtures do not certify every physical OS keyboard or IME. The separate source19 latency series still failed its sub-100-ms p98 target twice. Earlier measurements and failures above remain historical evidence.

This repair changes input ownership and provenance only. It does not reduce the 3D intro's geometry, effects, lighting, camera or choreography, and it does not establish physical iOS/Android keyboard behavior or field latency.
