# Actionable personal analytics

`SessionInsightsPanel` is mounted in the existing lazy result surface; `LearningDashboard` is mounted in Stats. Neither subscribes to the live input stream. They preserve headline metrics, attempt accuracy, word credit, correction policy, cohort identity and personal/server verification boundaries.

Per-key and reference-finger evidence comes from canonical replay and the existing learning-attempt projection. Corrected errors remain attempts. Attributable latency excludes first, paused, idle and simultaneous/composition intervals. A missing latency remains unavailable. The reference finger is a layout assignment, not observed anatomy. Bigrams require adjacent canonical target positions, avoiding invented pairs from correction retries. Smoothed accuracy is `(correct+1)/(n+2)`; a persistent problem requires at least20 observations and a value below92%. Lower-sample mistakes can still suggest a drill with an explicit limited-evidence explanation.

`typing-edit-diagnostics-v1` describes final-word edits independently of scoring. It uses an original optimal-string-alignment dynamic program, with equal-cost precedence: exact match, adjacent transposition, substitution, omission, extra. A neighboring physical reference-key substitution is labeled separately as a possible slip. This is an explanatory heuristic, not a physiological or intention classifier. Word diagnostics stop at256 graphemes per side and report truncation. Untyped timed suffixes are excluded. Unicode graphemes, repeated letters, ambiguous alignments and contextual edits have dedicated tests. Diagnostic counts must never be substituted for insertion-error counts or used to award progress.

The attempt-rhythm canvas is a static post-test rendering of canonical replayed duration-weighted buckets, rather than caller-supplied graph values. Exact time/rate/error values remain in its HTML data table. Finger bars and a numbered radial reference chart have labels, values and underlying key tables; an unobserved finger has no measured point. Separator attempts remain available for reference-thumb measurements. The keyboard map toggles attempt accuracy and attributable latency. Base/Shift forms on the same reference key use count-weighted accuracy and latency; each separate character remains in the table. Unsupported native physical layouts display an honest unavailable notice and preserve their measured character table. No chart depends on animation or color alone. The existing WPM/raw/errors graph remains intact. This implementation makes no 60-fps canvas animation claim.

The dashboard shows local-calendar today, past 7/30 days and all-time session/time totals, with separate PB rows for every full comparison key. The visible cohort label now includes correction policy, so legacy strict and correct-word locking remain distinguishable. PBs are personal observations, not population rankings. Existing calendar/history/export views remain available. Review and course-star summaries obey current-owner evidence and retained-assessment rules described in `learning/TRAINING_V2.md`. The existing Recharts speed chart is split into `StatsSpeedChart` and imported only when a user selects a comparison containing actual matching observations. The chart retains its visual contract, tooltip, static motion and history-table alternative, with a same-height loading fallback. Export errors are reported on the page rather than becoming unhandled rejections.

The1200×630 share card uses a pure paint contract. Its canonical statistics projection excludes owner/session IDs, names, passage text, individual errors, timestamps, cohort data and event logs. The image contains the wordmark, mode, duration and two measured headline values. No optional personal-data field is currently offered. JSON export retains the existing explicit detailed-export behavior. Paint-position/privacy unit tests are not a browser pixel snapshot or an actual hosted OG acceptance test.

Verification receipts live under `audit/mega-pack-2026-10-21/`. Initial failures remain recorded. Browser/axe, full integrated source gates, PHP parity, final route bundle sizes, physical accessibility and performance must be assessed by the coordinated release gates. No hosted or human learning outcome is claimed here.
