# Classroom lite

Classrooms provide private small-group practice and participation summaries. They are not public rankings, verified identity services or employment certifications. No student email, birth date, third-party tracker or invitation message is needed. Teachers should choose aliases that do not identify children outside the group; this is a privacy-conscious default, not a COPPA/GDPR compliance certification.

Device-only classrooms work in the frontend-only build. Their labels do not connect browsers or become online join codes. A teacher can enter or import at most100 bounded alias aggregates per class and export them explicitly. Imports are always labeled manually reported, even if an imported file claims server verification. Code labels and session/member IDs are excluded from the report exchange. Storage keys are owner-scoped. Corrupt saved data is preserved instead of overwritten; full/blocked storage uses an explicitly reported memory fallback. Stale adapters cannot overwrite another tab or resurrect owner-cleared data.

The server mode uses `ClassroomService` and additive `backend/migrations/003_classroom.sql` after the base schema. Importing this migration is an administrator operation; implementation checks do not modify a running user database. A missing migration returns an actionable503. Teachers authenticate through the existing cookie account. Teacher list/create/delete routes remain bound to the expected current owner. Deleting the teacher account cascades its classes, members, assignments and receipts.

Teachers choose **Refresh progress** to fetch the latest explicitly shared aggregates. There is no inferred or periodic progress simulation. Refresh replaces only the report list, preserving any displayed private code and active student input/result. Expected-owner and request-generation checks discard foreign or stale responses, including a slow initial read that completes after the explicit refresh. The button exposes a disabled/busy state while the request is pending and announces success or a real error.

Private join codes contain128 bits from `random_bytes`, shown only after creation. Storage has a SHA256 lookup plus independently salted verifier, not the plaintext code or a new required deployment secret. High entropy prevents a practical dictionary search; this is not password hashing for a user-selected password. Joining uses the shared origin/CSRF gates and a central10-per-minute IP rate gate. The narrow `$_SESSION['classroom_student']` capability holds a member/class identity; it does not replace or reset a signed-in account. A returned UUID is an identifier, never a bearer credential. Aliases alone cannot recover another membership. One active classroom membership is retained per browser session.

Students receive an issued original English/QWERTY assignment. An explicit Share aggregate result action sends its canonical candidate with `shareConsent:true`. The server checks the exact assignment contract and uses the independent `SessionValidator` with the processing consent. Actual pause/input-method dimensions remain canonical; text, generator, class identity and arbitrary configuration fields cannot be changed. The teacher receives numeric aggregates only. Classroom storage retains duration, attempt/correct counts, correct retained characters, WPM, receipt identity and canonical SHA256 hash; it never stores the submitted target, typed text, event list or key sequence. This proves replay mathematics, not a human identity or independent physical typing.

Submission is idempotent by issued assignment/session UUID. A different canonical payload for an already accepted ID conflicts. There are bounded20-class,100-alias and1,000-receipt-per-alias limits. SQL mutations are transactional and scoped; the next assignment is issued after an accepted receipt. Leaving explicitly deletes the current membership and its reports. Clearing cookies loses that session capability; ask the teacher to manage class data rather than expecting alias-only authentication.

Participation summaries use a client1200×800 PNG or browser Print / Save PDF, with no external dependency. Alias inclusion is off by default. No code, email, event text or timestamp is included. Manual reports say they are unverified; replay-checked reports still state that human identity and independent typing are unverified. Browser print/PDF availability varies by device.

The domain tests cover identity/size bounds, combining-mark aliases, forced manual import provenance, code-free exports, corrupt/full/blocked storage, owner and cross-tab deletion boundaries, plus certificate escaping/privacy. If storage becomes blocked during a visit, subsequent edits explicitly use memory. If durable deletion fails, memory is still cleared and stale adapters are invalidated; the failure explains that persistent reports may remain and deletion must be retried. This is best-effort cleanup, not a false successful deletion claim.

`npm run test:classroom-php` checks the issued contract and independent native replay without loading private configuration or connecting to SQL. It compiles the TypeScript reference into its own temporary ES2022 JavaScript bundle, so the supported Node22.12+ runtime does not need experimental TypeScript stripping/transformation. Temporary output is removed in `finally`. Optional `CLASSROOM_CONTRACT_REPORT` chooses a new receipt path; existing files are never overwritten, and the default report name includes a timestamp/process identity. The opt-in `node backend/tests/classroom-lifecycle.mjs` is prepared for the parent-owned fresh ephemeral instance only: it requires `SPAROWTYPE_PACK_HTTP_ACCEPTANCE=1`, explicit `SPAROWTYPE_CONFIG_FILE`, loopback `SPAROWTYPE_TEST_API_URL` and optional `SPAROWTYPE_CLASSROOM_HTTP_REPORT`. Its fixture rejects normal application databases/ports and requires the exact ephemeral schema/cookie namespace. It creates one uniquely reserved teacher, uses guest capability clients, and removes only its own teacher account. It never resets global rate counters. The harness checks actual CSRF, owner binding, student/account isolation, consent, canonical replay, idempotence, aggregate privacy and cascade deletion when executed; source existence does not establish a pass.

Full SQL/HTTP lifecycle, final delivery packaging and physical-device printing remain separate release gates. Prepared browser cases live in `e2e/classroom-lite.spec.ts`; parent checkpoint browser results must be associated with their specific build, rather than assumed to cover later source. Migration003 records schema version3 after all its tables are created.
