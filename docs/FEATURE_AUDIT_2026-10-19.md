## 2. Confirmed issues corrected during this audit

| Comparison cohorts | Inactive punctuation/numbers switches leaked into quote/code/custom/free-writing cohorts | Fresh configurations retain these dimensions only when generated words actually use them; historical/retest configurations remain immutable |

The strict current-word correction policy itself predates this audit and remains deliberate: an entered prose space commits the previous word, including mistakes. Code/free-writing whitespace follows the canonical JavaScript boundary rules. Backspace can edit the active suffix but cannot repair a submitted word. Blocked boundary deletion does not invent a deletion action or remove the original incorrect insertion from accuracy.

### Independent PHP replay/security review

Six additional defects were reproduced during review and corrected before final backend acceptance:

| Finding | Reproduction/impact | Correction and regression scope |
| --- | --- | --- |
| Numeric grapheme-cache keys | PHP converted digit strings to integer array keys; `array_shift` then renumbered entries, allowing `units('0')` to return the cached character `'1'` after eviction | Nonnumeric cache keys and key-preserving eviction; numeric/cache-churn parity cases |
| Indic mixed-base merging | A virama after a Latin character or space was incorrectly merged with a following Indic consonant | Official Unicode 15.1 InCB property data and the required leading-consonant GB9c sequence; positive conjunct and mixed-base boundary cases |
| Composition ID `"0"` | PHP treated this string as false while JavaScript treats it as a nonempty identity, changing deduplication and timing attribution | Explicit nonempty-string checks in replay and learning/key projections; zero-ID regressions |
| Whitespace mismatch | PCRE `\s` included U+0085/U+180E while ECMAScript `\s` excludes them, changing code/free correction boundaries | Explicit ECMAScript whitespace semantics and edit/key-summary parity cases |
| Malformed scoring policy | An array policy reached a string return type and raised `TypeError`, which the API presented as HTTP 500 | Explicit type validation and malformed-policy rejection cases; invalid client input is rejected as validation failure |
| Password verification policy | The fixed dummy hash used bcrypt cost 10 while PHP 8.4's `PASSWORD_DEFAULT` can use cost 12, weakening the intended uniform wrong-password work | Real and dummy bcrypt verification use explicit **cost 12**; password-policy checks also preserve significant password bytes beyond bcrypt's direct 72-byte input boundary |

These fixes concern specific demonstrated failures. They are not a formal penetration-test certificate or a proof that every Unicode/browser combination has identical behavior.

### Additional final-review repairs

- A delayed profile identity response could overwrite an edited handle; same-account auth updates could refetch and reset the draft. The initial handle now waits for its identity request, and the effect is scoped to account ID. Three deterministic regressions cover delay, same-account refresh and fetch-error recovery; all passed on four engines alongside the real account lifecycle in the final 20-case confirmation.
- Competitive evidence is preflighted before expensive replay. It permits one grapheme per nonempty keyboard edit, at most 80 insertion attempts per rolling second, and after five seconds at most 500 headline WPM or 650 attempt WPM. These are conservative automation heuristics, not proof of human typing. Ordinary personal bulk/IME practice retains its separate contract.
- Aggregate submitted insertion evidence is bounded to 20,000 UTF-16 units, including rejected/deleted attempts, before replay allocation. Oversized results remain local rather than receiving a fabricated server acceptance.
- Explicit stale-owner submission hints return a conflict; human race evidence must use its room endpoint. Post-deadline receipt grace does not permit a leave action to change the winner, automatic matches require a fresh host heartbeat, and ranked issue/redemption share the same MySQL clock.
- Hosting packages are staged from scratch. Manual old config/storage/stale assets stay in an ignored archive and cannot leak into the fresh shipping tree. Actual Apache checks and source hashes cover the generated package; no private config is shipped.

## 3. Active architecture after the migration

| Layer | Implementation and responsibility |
| --- | --- |
| Browser presentation | React/TypeScript routes, preferences, results, virtual keyboards and the retained Three.js intro |
| Canonical browser engine | `src/lib/typing-core/`: monotonic session timing, grapheme transcript edits, word credit, metrics, replay and current-word correction |
| Explicit PHP transport | `src/services/php-api.ts`: configurable `VITE_API_BASE_URL` (`/api` by default), credentialed JSON requests, in-memory CSRF token, one bounded CSRF refresh and typed errors |
| Authentication | PHP cookie sessions with HttpOnly/SameSite settings, session/CSRF rotation, password hashing, expected-owner checks and database-backed rate limits; no bearer token in browser local storage |
| Account state | Auth event ordering and cross-tab change notifications; a notification triggers a server identity read and is not itself trusted as an identity |
| Persistence | IndexedDB/local fallback for device history; PDO prepared queries and MySQL/MariaDB InnoDB tables for account records, accepted results, preferences, identities and races |
| Native server replay | `backend/src/SessionValidator.php` independently replays the portable contract and derives accepted metrics, chart, comparison key and learning projections |
| Account APIs | Session history/version snapshots, optimistic preference updates, handle changes, immutable upload receipts, per-session deletion/tombstones and explicit account deletion |
| Competition | Server-owned human-room/challenge protocols; cookie-authenticated polling replaces Supabase Realtime. Local bots remain visibly identified as bots |
| Hosting | XAMPP/PHP development support, phpMyAdmin-importable `backend/schema.sql`, Apache routing/security configuration and hosting packaging helpers |
| Offline | Public application-file cache and generic recovery shell; authenticated/private API traffic is excluded from the application cache |

The browser never receives database credentials. Database configuration and private PHP sources belong outside the public document root. Cookie `Secure`, trusted origins, session storage, HTTPS, database privileges and cleanup scheduling must be configured for the actual public host.

**Retention distinction:** the server's 90-day replay expiry removes the raw session replay and race transcript fields. Adaptive learning projections are separate records: their ordered per-key expected/typed characters and timing can remain after raw replay expires. For public lessons this can reconstruct portions of the practiced text and behavior. Replay expiry is therefore not deletion of all character-level learning data. Private custom/free-writing sessions do not receive this public-lesson learning projection; deleting a session/account remains the control for removing its associated stored evidence. Deployment privacy copy and retention policy must describe both forms of storage accurately.

Google OAuth is **not implemented in the PHP backend**. The earlier provider button was removed rather than presented as working. Email/password accounts are the active authentication flow. A future OAuth integration requires a real provider configuration, state/PKCE handling as applicable and separate acceptance tests.

Email/password signup signs in immediately. Email delivery, email verification and a password-reset workflow are **not implemented**. This is a fresh account backend: previous Supabase passwords and account IDs are not imported. Device history remains in its original owner scope, and guest import is explicit. A verified export and identity mapping would be needed to migrate an earlier live account database.

## 4. Metrics and typing behavior retained

- **Input accuracy:** correct insertion attempts divided by all insertion attempts. Original errors remain counted after correction. Deletion is recorded separately and is not an insertion attempt.
- **Headline WPM:** credited prose characters divided by five and elapsed minutes. Correct completed words and their actual separators receive credit; a timed final partial word can receive leading-prefix credit. Code uses correct-character credit and a separate comparison cohort.
- **Raw WPM:** retained characters, including errors, divided by five and elapsed minutes. Attempt rate also includes inserted characters later deleted.
- **Final-text accuracy:** correctness of processed final text, including missed/extra positions; this is separate from original-input accuracy.
- **Consistency/burst:** duration-weighted attempt buckets, including idle time, with minimum-evidence requirements. Missing evidence is displayed as unavailable rather than an invented score.
- **Timing:** `performance.now()` owns the browser session clock; presentation refresh timers do not determine elapsed time. Explicit practice pauses are recorded and compared separately. Races/challenges use server-owned starts and deadlines.
- **Input:** grapheme-based edits, NFC prose, exact code normalization policy, composition ownership, blocked paste/drop, actual wrong-character feedback, caret geometry and rapid fresh-session restart remain in place.

These policies intentionally do not promise numerical parity with every Monkeytype or Keybr statistic. Retrofitting a different formula would require an explicit metric/version/cohort migration; this audit does not silently rewrite historical results.
