Eleven new unit cases cover speed rounding boundaries and sparse/inherited/getter/proxy target-count semantics. These changes removed work, but source28's later failed measurements did not establish a sufficient latency gain.

Source31 adds layout containment around the fixed typing stage and Learn stream wrapper, plus strict containment on the invisible, fully positioned native Learn input. This confines browser editing/layout work while retaining the visible passage, current keyboard, input semantics and complete3D scene. The source28 trace observed broad layout spans before application event dispatch; it motivated a bounded layout experiment rather than a claim that JavaScript alone caused the delay. [MDN's `contain` reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain) describes the isolation boundary and the sizing implications of strict containment. [Chrome's interaction-layout guidance](https://developer.chrome.com/docs/modern-web-guidance/guides/performance/interactions-in-complex-layouts) explains how containment can reduce page-wide reflow. Both primary sources were checked **2 November 2026**. The one passing candidate trial remains empirical scope; physical IME/viewport and full cross-engine behavior still require verification.

Retained earlier input changes avoid needless passage/keyboard allocations, cache current session text with invalidation before applying edits, and restrict transcript mutation shortcuts to privately branded immutable-target slots. Physical key feedback updates its owned DOM attribute without rerendering the whole guide on plain press/release. Cleanup and subsequent commits repair ownership. The **2D** caret and key transform durations are55 ms; the ripple remains240 ms. This is independent of the preserved3D animation.

Practice timing starts on the **first accepted insertion**. Live human races retain their shared authoritative server clock. Canonical attempt accuracy, corrected-error history, Unicode/composition, current-word correction and server validation contracts remain applicable. No display optimization may weaken evidence or change clock semantics.

The retained backend uses atomic rate counting, live authentication-version checks, prevalidation before room/account locks and a DB receipt captured before preparation. The authoritative elapsed-time replay and current membership/prefix/status/issuance/grace checks remain inside the locked stage. Source31 moves public handle lookup to response serialization, leaving fresh complete member rows and their original `FOR UPDATE` locks in internal operations. Its single-entry per-validator cache stores only word boundaries for the exact target-array value; changing the target invalidates the entry. PHP copy-on-write prevents returned arrays from mutating the cached boundaries. It caches no transcript state, timing allowance or authoritative result. The23 member/response-byte and34 cache contracts supplement complete canonical parity. No authoritative replay is hoisted or cached across requests.

Compact Arena uploads omit only `characters`, `timeSeries` and `cursor`, which the server reconstructs before canonical hashing; raw events, targets, metrics, owner and privacy remain. Full local exports retain their evidence. Ordinary JSON decoding avoids duplicate allocation while the raw `\u0000` fallback preserves the former error contract, including overwritten duplicate-key subtrees. See the [backend ledger](ARENA_CAPACITY_2026-10-27.md) for exact changes, rejected experiments and preserved failures.
