# Offline practice, route metadata and secondary pages

Implemented 16 October 2026. Existing `forge-v3` metric, learning, owner, repository and cloud identifiers are preserved.

## Pages and navigation

- `/privacy` explains local versus cloud data, private passage consent, replay retention, exports, Keyboard Lab and public app caching. It does not invent a deployment operator or legal compliance certification.
- `/terms` gives clear practice, content, account, competition and availability conditions without claiming a qualification, accreditation or fixed improvement.
- `/offline` shows actual public download status, provides update/install controls where supported, removes only the public app cache, and explains the difference between a download and a history backup.
- `/touch-typing` provides an actionable setup → manageable letters → correction policy → baseline/practice/retest routine. Posture and home-row descriptions are references; the browser cannot detect actual fingers or technique.
- The 404 route now uses the standard header/footer and `main-content` target, with three real recovery links. An unknown address no longer creates an artificial console error.
- `/typing-test` uses the actual test workspace; `/typing-practice` and `/practice` use the actual adaptive workspace. They are aliases, not independently measured new products.

## Search metadata

`src/lib/seo.ts` defines distinct titles and descriptions for public intents. `applyRouteSeo` updates document title, description, robots, Open Graph and Twitter text, plus a self-origin canonical URL for indexable pages. Alias canonical URLs point to the existing root or learning workspace. Private/operational pages, unknown paths and room IDs receive `noindex,nofollow` and no canonical/OG URL. Arbitrary query values and private room IDs are not interpolated into metadata.

No production hostname or social image is invented. `SPAROWTYPE_SITE_URL`, when supplied to the build, creates a sitemap containing public content routes only and adds its real origin to generated robots.txt. An unset origin removes any earlier generated sitemap reference. Existing root robots rules stay crawlable so a crawler can encounter `noindex`; robots rules are not authorization. [Google Search Central: noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing)

**UNVERIFIED:** authoritative indexing, social crawler rendering, hosted canonical behavior and HTTP status/headers. This remains a client-rendered SPA; metadata takes effect after JavaScript executes. A deployment can additionally provide route-specific `X-Robots-Tag` headers for private/operational paths. The SPA host’s response to unknown URLs must be checked for soft 404 behavior. Browser metadata assertions do not certify search placement.

## Public offline cache

`public/sw.js` is a template, not an install-ready worker. Run `node scripts/build-offline.mjs` after Vite. The script reads actual emitted assets, computes a deterministic content version and generates:

- `dist/sw.js` with the exact public file allowlist;
- `dist/_offline-recovery.html`, a generic connection-recovery document distinct from the routed `/offline` app page;
- `dist/offline-build.json`, public file count, bytes and content version;
- an optional real-origin sitemap when configured.

The worker registers only in a production build and a supported secure context. Installation downloads the generic HTML shell, recovery page, emitted scripts/styles/fonts/images, self-hosted `/fonts/` CSS and font files, and root public icon/manifest files with omitted credentials. Runtime requests never write new responses into the cache.

All cross-origin traffic, including Supabase, bypasses the worker. Same-origin API/Auth/REST/functions/storage/realtime prefixes, non-GET requests and requests carrying Authorization also bypass it. Query-bearing asset requests are not intercepted. Public navigation uses the network first and the generic shell on network failure; private/unknown document navigation receives only generic offline recovery if disconnected. No personalized document or API response is added to CacheStorage.

The cache namespace is `sparowtype-public-v1-<content version>`. Activation retains two previous public builds for older tabs that may still need lazy chunks, and leaves all other cache namespaces alone. A downloaded update waits for the user to choose reload or for older controlled tabs to close. Reload is never automatically triggered merely because an update exists. Browser service-worker installation, waiting and activation are distinct states. [MDN: Using service workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)

The optional native installation prompt is invoked only by the user’s install button. Acceptance is described as a request; an installed event or standalone display identifies installation. Browser and platform install behavior varies. [MDN: Installable PWAs](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

“Remove offline download” unregisters this app’s known registration and deletes only its public cache namespace. It never resets IndexedDB, localStorage, preferences, learning history or account data. An already open tab can retain its controller until it closes. Browser storage can be evicted; an offline cache is not a backup. Cloud uploads/races/rankings still need their normal authenticated backend and cannot become verified merely by working offline.
